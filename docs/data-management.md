# 公式CSV・複数アカウント・バックアップ

自己ベストを公式プレーデータCSVから取り込む方法、複数アカウントの使い分け、
設定とプレーデータのバックアップ方法を説明します。

## 公式プレーデータCSVを取り込む {#official-csv}

公式サイトからダウンロードしたプレーデータCSVを、選択中のアカウントの自己ベストとして登録できます。
CSVファイルそのものはアプリ内へコピーされません。取り込んだ自己ベスト、最終プレー日時、
譜面ごとの公式プレー回数が、選択中アカウントの `daken_counter.db` に保存されます。

1. 複数アカウントを使っている場合は、先に「アカウント」メニューで取り込み先を選びます。
2. 「ファイル」→「公式CSVをインポート」を開きます。
3. 取り込むCSVに合わせて **SP** または **DP** を選びます。
4. CSVの内容を入力欄へ貼り付けるか、CSVファイルを入力欄へドラッグ＆ドロップします。
5. 「インポート」を押し、完了メッセージを確認します。

選んだSP／DPは保存され、次回の画面で復元されます。UTF-8のBOM付きCSVと、タブ区切りで
貼り付けられたデータにも対応しています。処理中はアカウントを切り替えられません。

既に同じ自己ベストがある譜面は重複登録せず、最終プレー日時や公式プレー回数など、
不足または更新された情報だけを反映します。公式プレー回数は
[`history_cursong.html`](obs-views.md#history) の `PLAY COUNT` で、打鍵カウンタ内の回数と並べて確認できます。

### 保存済みログの補正を確認された場合

保存済みのスコア・ミスカウント・クリアタイプが公式CSVの値を上回る譜面があると、
補正対象、保存済みベスト、公式ベスト、削除されるログ数が表示されます。
「はい」を選ぶと、公式値を超えている通常プレーのログを削除してから公式値を登録します。

この削除は設定画面のキャンセルでは元に戻せません。内容に心当たりがない場合は「いいえ」で中止し、
[バックアップ](#backup)を作成してから再実行してください。

## 複数アカウントを使う

メニューバーの「アカウント」→「アカウント登録・編集」から、アカウントを追加・編集できます。
アカウント名、メイン画面で使う表示色、任意の画像保存先を設定します。
画像保存先を空欄にすると、「基本設定」→「画像保存」の共通設定を使用します。

登録済みの名前は「アカウント」メニューに並びます。プレー中、リザルト処理中、
公式CSVの取り込み中を避けて、使用するアカウントを選んでください。
アカウントを切り替えると、次の情報も切り替わります。

- プレー履歴、自己ベスト、公式CSVから取り込んだ情報
- ライバルの登録内容と取得済みデータ
- アカウント別の画像保存先

画面取得、OBS、音声案内、オーバーレイなどの基本設定と、`inf_score.csv` の出力先は全アカウント共通です。
RANDOMレーン認識で登録した正規譜面も共通の `random_lane.sqlite3` を使用します。

デフォルトアカウントは削除できません。追加したアカウントを登録一覧から削除しても、
`accounts` フォルダ内のデータファイルは自動削除されません。

### アカウント情報はどこに保存されるか

アカウントの定義は、アプリのフォルダにある `config.json` の `accounts` に保存されます。
保存されるのは、アプリ内部のアカウントID、表示名、表示色、画像保存先、ライバル設定です。
最後に選択していたアカウントのIDも `selected_account_id` に保存されます。

KONAMI ID、e-amusementのログイン情報、パスワードは保存しません。
公式サイトから取り込んだCSVの原文も `config.json` には保存しません。
ただし、`config.json` にはOBS WebSocketのパスワードやライバルCSVの共有URLなど、
ほかの設定も含まれます。バックアップを他人と共有しないでください。

プレーデータの保存先は次のとおりです。

| 対象 | 保存先 |
| --- | --- |
| デフォルトアカウント | `daken_counter.db` |
| 追加したアカウント | `accounts/<アカウントID>/daken_counter.db` |
| 全アカウントの定義・最後の選択 | `config.json` |
| RANDOMレーン認識の登録譜面（共通） | `random_lane.sqlite3` |

追加アカウントのフォルダ名には、画面の表示名ではなくアプリが自動生成した内部IDを使います。
フォルダ名を手作業で変更しないでください。

## データをバックアップする {#backup}

### 最も確実な方法

1. 打鍵カウンタを終了します。タスクマネージャーにも `notes_counter.exe` が残っていないことを確認します。
2. アプリのフォルダを、日付を付けた別フォルダやZIPへ丸ごとコピーします。
3. 画像保存先、CSV出力先、RANDOMレーン認識のテンプレートフォルダをアプリ外に指定している場合は、
   必要なフォルダも別途コピーします。
4. バックアップ先に `config.json` と `daken_counter.db` があることを確認します。
   追加アカウントを使っている場合は、`accounts` フォルダも確認します。

アプリを終了してからコピーすることで、書き込み中のSQLiteデータを避けられます。
複数アカウントを使っている場合は、`config.json` と `accounts` フォルダの片方だけでなく、
必ず両方を同じ時点でバックアップしてください。

### データだけを選んでコピーする場合

| 優先度 | ファイル・フォルダ | 内容 |
| --- | --- | --- |
| 必須 | `config.json` | アプリ設定、アカウント定義、ライバル設定 |
| 必須 | `daken_counter.db` | デフォルトアカウントのプレーデータ |
| 使用時は必須 | `accounts` | 追加アカウントのプレーデータ |
| 使用時は必須 | `random_lane.sqlite3` | RANDOMレーン認識で登録した正規譜面 |
| 任意 | `results` または設定した画像保存先 | 保存済みリザルト画像 |
| 任意 | 設定した配置認識テンプレートフォルダ | RANDOMレーン認識用テンプレート |
| 任意 | `playlog.infdc`、`out/rival_log.infdc` | 旧v3から変換した元データ |

`inf_score.csv` はデータベースから再出力できます。`log`、`tmp`、`runtime_state.json`、
`out/websocket.css`、起動中だけ保持する一時リザルト画像は、通常の復元には不要です。
調査用ログも残したい場合は `log` フォルダを任意でコピーしてください。

### 復元する

1. 打鍵カウンタを終了します。
2. 復元先の現行データも、上書き前に別の場所へコピーします。
3. 同じバージョンへ戻す場合は、バックアップしたアプリのフォルダ一式を復元します。
4. 新しいバージョンへ移す場合は、最新版を空のフォルダへ展開してから、上表のデータだけをコピーします。
5. 起動後にアカウント一覧を開き、各アカウントへ切り替えてスコアビューワの内容を確認します。

`config.json` だけを復元して追加アカウントのDBがない場合は、空のDBが新規作成されます。
反対に `accounts` フォルダだけを復元しても、対応するアカウント定義がないためメニューには表示されません。
